磨损识别准确率测试大纲制定思路说明

这份材料主要给项目组内部交流使用。目标不是写得很学术，而是把“为什么测试大纲要这么写”这件事，用更直接、更容易讨论的方式说明白。

1 这份材料是做什么的

这份材料是发给项目组成员交流使用的说明稿，用来回答一个实际问题：

为什么当前测试大纲没有把“磨损识别准确率”直接写死成某一种算法指标？

它不是正式测试依据，正式测试仍以测试大纲和测试报告为准。

2 现在遇到的核心问题

当前项目的实际应用场景为日常使用中的镜片磨损程度识别，与生产端缺陷检测场景存在明显差异。

生产端通常是：

  • 缺陷少
  • 缺陷相对独立
  • 一个缺陷对应一个目标，比较容易数清楚

而我们现在的镜片磨损图像更常见的是：

  • 磨损很多
  • 相互重叠、粘连、交叉
  • 很多时候很难稳定地说“这里到底是几个独立缺陷”

因此，若完全照搬生产端“独立缺陷实例检测”的指标体系，会与本项目真实业务目标存在偏差。

3 现有实验给了我们什么提醒

3.1 当前检测方案是能工作的

当前测试版本 LWIA-Det v1.0.0（内部训练注释：B2_nwd_only_phase3e）在完整测试集上的结果是：

  • mAP50 = 0.6844
  • Precision = 0.6030
  • Recall = 0.6725

这说明：当前检测方案已经可以作为正式送测版本使用。

3.2 但分割实验说明，真正难点不只是“框出来”

第二批分割实验里，几个模型在私有数据上的表现并不一样：

  • FPN private best_loss = 0.2904
  • HRNet-OCR-W18 private best_loss = 0.3029
  • SegFormer-B2 private best_loss = 0.3258

这说明后续技术路线很可能会从“目标检测”逐步转向“区域识别/分割增强”。

3.3 形态规则结果说明，重叠区域确实很复杂

当前形态规则分类的统计结果是：

  • n_images = 197
  • n_components = 91235
  • uncertain = 16610

这说明很多区域并不是简单数目标就能说清楚的，尤其是重叠、粘连和复杂形态区域。

4 我们讨论过的几种写法

方案一：测试大纲直接写死为 mAP50

好处是最标准、最容易送检、和当前实现完全一致；问题是后续如果改成区域识别，测试大纲就会被卡住。

方案二：写成“正确检出数量 / 全部标注数量”

好处是好懂；问题是太像检出率，不够严谨，也容易被质疑。

方案三：直接把区域重合度当正式指标

好处是更接近真实业务目标；问题是现在就这么改，第三方容易觉得这是自定义指标，而且当前送测版本也不是按这个口径实现的。

5 最后为什么定成现在这个版本

5.1 指标名字不变

统一叫：磨损识别准确率。这样和任务书一致，也方便后续沿用。

5.2 定义写成上位表述

测试大纲里不把它直接绑定成某一个固定公式，而写成：

被测软件产品在规定测试图像集上，对磨损目标识别结果与基准结果一致程度的评价指标。

这样做的好处是：当前检测方案能用，后续区域方案也能接。

5.3 当前怎么执行

当前送测版本还是目标级检测输出，所以：

  • 当前正式测试继续按目标级评价方式执行
  • 当前正式结果写成 mAP50

也就是说，当前没有改送测指标，只是给后续技术路线留了空间。

6 现在这套写法的实际意义

对当前送测来说：

  • 不影响现在的检测测试
  • 可以直接使用现有成熟结果

对后续改进来说：

  • 如果以后转向区域识别，不需要把整个测试大纲推翻重写
  • 只需要在委托测试文件和测试报告里明确当前采用的评价方式

7 一句话结论

指标名称先稳住，当前检测照常送测，后续区域方案也能接进来。

这就是当前版本想解决的核心问题。
